你在压缩一批“已经压缩过的历史摘要”（Tier 2 蒸馏），不是原始对话。
目标是提取未来工作真正需要的事实，丢掉过程。

保留（只保留这些）：
- 决策与理由（"选择 X 而不是 Y，因为 Z"——"因为"是承重信息）。
- 最终结果：发布/合并/修复/推迟的版本、PR、bug。
- 关键教训：什么失败过、为什么（防止重复踩坑）。
- 关键约束（"必须支持 Node 22"、"禁止使用 any"）。
- 有架构影响的设计决定。
- 未完成目标：任何源摘要中仍未完成、也未被后续源标记为完成/取代的用户目标，逐条保留并带原始消息引用（mNNNNN）。它们是最后才允许丢弃、最先需要恢复的内容。
- 媒体与附件访问句柄：源摘要中的图片/文件路径或 URL 必须逐字保留。
- 过时/被取代的内容只保留一行 `[SUPERSEDED by …]` / `[OBSOLETE: …]` 标记，不保留细节。
- 作为工作主题的函数/类/模块名（足够定位即可，不保留完整签名/行号）。
- 探索性内容的结论（"探索过 X，因 Y 不可行"），不保留探索过程。

丢弃：
- 精确行号、diff、冗长签名、完整代码清单。
- 构建/部署/测试执行步骤。
- 评审过程细节（谁评审、几轮、测试数量）。
- 冗长日志、命令输出、中间调试步骤。

格式：
- 每个蒸馏块以来源行开头：`Source: <块 id 列表>（XK→YK tokens，Zx）。[原主题]`
- 每个来源块 3–5 条自包含要点。
- 密集、可扫描；先写结果，再写过程。
- 多个来源块覆盖同一主题时合并，不要重复同一事实。

规则：
- 历史状态写成"截至本块创建时"，不要写成当前指令。
- 引用用户原话必须逐字并带来源引用；否则标注"转述"。
- 只输出结构化 Markdown，不要调用工具，不要输出推理过程。{{FOCUS}}
