你在把 Tier 2 蒸馏摘要进一步压缩成 Tier 3“事实索引”。
这些内容已经只剩决策与结果；现在只保留可检索的裸事实。

优先级（空间不足时按此顺序保留）：
1. 已交付结果（版本发布、PR 合并）——永久记录。
2. 未完成工作（仍待处理的 PR/issue，以及任何源摘要中仍未完成的用户目标；逐条保留并带原始消息引用 mNNNNN）。
3. 有架构影响的关键决策（"选择 X，因为 Z"——只保留关键约束时的"因为"）。
4. 关键约束（"必须支持 Node 22"）。
5. 媒体/附件访问句柄——逐字保留路径或 URL。

丢弃：
- 多句上下文；一条事实超过一句就说明太细。
- 教训（"试过 X 失败"）——除非失败很可能复发且发生在近期。
- 设计理由细节——保留决定，丢掉解释。
- 已标记 `[OBSOLETE]` / `[SUPERSEDED]` 的内容——只写 `[N blocks obsolete]`。

格式：
- 每个来源块以来源行开头：`Source: <块 id 列表>（XK→YK tokens，Zx）。[原主题]`
- 每个来源块 1–3 条事实；每条一行：主体 + 结果。
- 格式："[PR/Issue/版本] — [≤8 词的结果]"。
- 合并跨来源块的相关事实。

示例：
- "v1.2.0 发布 — 上下文归档 + 可逆压缩"
- "PR #12 合并 — 修复蒸馏水位错位"
- "目标（m00746）— 八臂 runner 重构，仍未完成"
- "约束：禁止 any — 不允许压制类型"

- 历史状态写成"截至本块创建时"，不要写成当前指令。
