# 上下文管理最佳实践

## 适用场景与入口判据

使用 `context`：

- 上下文占用过高、响应变慢或被截断时，主动压缩较早对话。
- 需要查证此前读过/讨论过的内容时，检索历史上下文。
- 长任务中需要恢复关键决策、路径、验收标准时。

注意：压缩会**物理移除**被折叠消息，摘要中未记录的内容无法再检索到。

## 推荐流程

1. 压缩前先确认关键信息已写入摘要或记忆：目标、验收标准、关键路径、决策、错误与修复、待办。
2. `action="compact"`，可传 `focus` 指定优先保留的内容。
3. 压缩后用 `action="search", scope="current"` 抽查关键信息是否仍可检索。
4. 需要跨会话恢复时用 `scope="all"`，可传 `query`、`includeTool`、`topK`（默认 10，最大 50）。
5. 上下文压力提醒出现时，先评估是否真的需要压缩；不要机械重复压缩。

## action / 参数速查

- `compact`：`focus`（可选，附加焦点）。
- `search`：`query`、`scope`（`current` 默认 / `all`）、`includeTool`（默认 false）、`topK`（1-50）。
- `includeCompacted` 是兼容字段；当前压缩物理移除原文，已折叠内容不可检索。

## 压缩前必须保留

- 用户目标与硬约束；
- 验收标准与验证命令；
- 关键文件路径、函数/类名、行号；
- 已确认的决策与理由；
- 错误信息、根因、修复状态；
- 未完成待办与阻塞项。

## 失败信号与恢复

- 压缩后关键信息丢失：用 `scope="all"` 搜索历史会话；仍找不到则向用户确认或重新读取文件。
- 压缩失败/空摘要：调用方会放弃本轮压缩；不要立刻重试同一参数，先检查上下文长度与模型可用性。
- 检索不到：换关键词、扩大 `scope`、开启 `includeTool`；不要把「没搜到」当成「没发生」。
- 压力持续偏高：优先减少工具结果体积、裁剪返回字段，而不是反复压缩。

## 验证与验收

- 压缩后抽查 2-3 个关键事实/路径是否仍可检索。
- 确认摘要中没有编造内容；不确定的事实标注为待确认。
- 确认待办和验收标准仍可执行。

## 禁止事项 / 反模式

- 不在未保留验收标准时压缩。
- 不把压缩当删除工具；它不可逆地移除原文。
- 不重复压缩同一段上下文。
- 不依赖未写入摘要的隐含信息。
- 不把工具结果全文塞进摘要；只保留结论、路径、错误与证据。
